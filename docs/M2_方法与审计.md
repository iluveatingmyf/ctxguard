# M2 情境因子词表：方法、审计与验证

> 对应论文第四章 4.2 节（情境因子空间的构建）。代码在 `ctxguard/vocab.py`（阶段 A–D）、`ctxguard/roughset.py`（粗糙集审计）、`ctxguard/versioning.py`（冻结、迁移）、`ctxguard/binding.py`（M3 与反驳）。命令顺序见 README「M2 详细步骤」。

---

## 0. 先把要求说清楚

**你的要求：**
1. 情境因子有哪些维度，要从 property 语料里总结出来，不能事先写死。
2. 然后用 agent 扩展每个维度的取值，以及取值的组合和 effect 的正/反面绑定关系。
3. 维度必须可审计，整个 M2 流程必须可审计、可验证。
4. 所有可能进 evaluation 的中间结果都要保留。
5. 讲清楚第二章 2.5 节的四个理论到底用到了没有，用在哪里。

**背后的意思：** 审稿人会问"凭什么情境就是这几个维度、这几个取值"。这个问题的回答必须是一串可复查的证据，而不是"我们认为"。词表是 K、在线判断和 RQ3 编译共同的地基，所以词表的每一处改动都要能追溯到证据，也要能重新算出来。

**这对项目意味着什么：** M2 交出的不是"一张表"，而是"一个能产出表、检查表、并且能继续长大的过程"。词表只在冻结那一刻固定成一个版本（F-v1、F-v2……）。新证据出现时，从当前版本增量地产生下一版。

## 1. 统一词汇与符号

| 符号 | 名称 | 含义 |
|---|---|---|
| P | property 语料 | 每条有 id、来源、原文；按 id 哈希固定划分为训练集（70%）和留出集（30%） |
| c | 情境条件 | 从一条 property 抽出的一句原子事实，例如"有人在房间里睡觉" |
| d | 维度 | 情境的一个侧面，例如"房间里的人在做什么"。对应一个或几个因子 |
| f = (name, semantics, D_f) | 情境因子 | 一个有限取值的变量；D_f 是它的值域 |
| s ∈ Σ ⊆ ∏ D_f | 抽象情境 | 每个因子取一个值；Σ 是去掉不可能组合（可行性约束）后的格子集合 |
| x | 现实情境 | 真实世界中的一个具体情形；它落进某个抽象格子 s |
| E、V | 效果、利益 | E 来自 M1（例如"声音增大"）；V 是 6 项受保护利益 |
| L(s, e, v) ∈ {+, −, 0} | 判定标签 | 在情境 s 下，效果 e 对利益 v 是好、坏还是无关 |
| φ | 条件模式 | 多值乘积项：若干"因子 ∈ 取值子集"的合取 |
| b = ⟨φ, e, v, ℓ, h⟩ | 绑定 | 在 φ 内，e 对 v 的标签是 ℓ，h 是损害机制 |
| K | 规范 | 全部绑定。没被任何绑定覆盖的格子默认标签为 0（封闭世界） |
| R_d | 证据对 | 引出过维度 d 的那些"效果 × 利益"对 |
| sig(c) | 标签签名 | 状态 c 在 R_d 上的标签向量 |
| F-vN | 词表版本 | 冻结后的因子集合，带父版本和 refines 映射 |

**一条贯穿全章的原则（粒度原则）：** 一个区分（多一个维度，或一个取值拆成两个）值得保留，当且仅当它会改变某个"效果 × 利益"的标签。E × V 是有限的，所以这个过程有上界，不会无限细分。用粗糙集的话说，我们要找的是"保持判定不变的最粗划分"（第 4 节）。

## 2. 总体流程与模块关系

```
property 语料 ──A1 抽取──> 条件 ──A2 开放编码──> 维度 ──A3 取值──> 语料词表
                                                                  │
                                                         A4 人工审核（R1–R4）
                                                                  ▼
                          M1 的效果 E ──┐                    种子词表 F_seed
                          利益 V ───────┼──B 按"效果×利益"引出──> 证据条目
                                        │                           │
                                        └──C 签名合并（对每个维度）──┘
                                                                  ▼
                                                    候选词表（含 refines）
                                                                  │
                                                     D1 人工审 + 冻结 F-v1
                                                                  ▼
                                    M3 在 Σ 上绑定（素蕴涵覆盖）→ K
                                                                  │
                         ┌────────── D2 粗糙集审计（核、约简、取值划分、素性）→ 维度卡片
                         │
                         └────────── D3 反驳（含 0 区域）→ 独立裁判 → 确认的反例
                                                                  │
                                       确认的反例变成新证据，回到 C（--base current）
                                                                  ▼
                               冻结 F-v2 → 迁移 K → 只重建待复核的对 → 再审计
```

**分工：**
- **阶段 A** 回答"有哪些维度"。不按利益过滤，只看语料。
- **阶段 B、C** 回答"每个维度要分几个取值"。必须按利益做，因为"好/坏"一定是"对谁"的。
- **阶段 D** 回答"这些维度和取值是否真的必要、是否足够细"。它用 M3 给出的完整判定表做精确检验，再用反例检验对现实是否过粗。

**利益在哪一步出场：** 找维度时不出场（A），判断维度和取值要不要保留时出场（B、C、D）。原因是，一个维度是否必要，只能对某个"效果 × 利益"来检验。例如"室外温度"对舒适和资源有影响，对安全没有影响。

## 3. 各阶段详述

每个阶段按同样的格式写：做什么，输入和输出，算法，可审计点（留下什么文件），可验证点（用什么数字检验）。

### A1 条件抽取（`m2-extract`）

- **做什么：** 训练集的每条 property，让 LLM 抽出其中的原子情境条件，并写成与设备无关的句子。再用一次单独的调用，标出这条 property 保护哪些利益。这个标注只用于统计覆盖率，不参与找维度。
- **提示词：** `extract_predicates_prompt`、`property_assets_prompt`。
- **输出：** `A1_conditions.yaml`，每行包含 property_id、条件、利益和原文。`A1_report.yaml`，包含各利益的 property 数和条件数，以及没抽出任何条件的 property。
- **可验证：** `m2_A1_extraction_CHECK.csv` 抽样 50 行，人工判断两件事：条件忠实于原文吗？描述的是世界状态吗？报告两项通过率。
- **论文里能写：** 语料对 6 项利益的覆盖是否偏向安全。这就是需要阶段 B 的理由。

### A2 维度发现：变量级编码（`m2-dims --runs 3`）

> **v2 修订（2026-10-31 第一次真实运行之后）。** 第一版的做法是：把全部条件一次性交给 LLM，让它"按主题归类"，再按"未覆盖比例"决定何时停止。7B 模型上的真实运行暴露了五个问题：
> 1. 每个候选维度都声称覆盖了 146 条中的 118–144 条，covers 字段没有信息量；
> 2. 产生了"security"这样以利益命名的维度，以及"device_status"这样与排除类重名的维度；
> 3. "environmental_conditions"把温度、湿度、空气质量打包成一个维度，又因为 `n_variables` 缺省而被限制成只能产生 1 个因子；
> 4. 第一轮就"零未覆盖"并停止。维度越宽越容易零未覆盖，所以这个停止条件奖励的是宽而错的维度；
> 5. A3 用一次调用同时生成取值和分配，3 个维度的覆盖率为 0。
>
> 稳定性实验已经抓到了这些问题：ARI = 0.40，5 个维度中只有 2 个复现。这本身就是审计机制有效的证据，论文里可以作为"迭代 1"报告。
>
> 根本原因：编码的单位选错了，是"主题"而不是"变量"；任务形式也不适合 7B 模型（长列表一次输出）。v2 把编码单位改成**世界变量**，并把每一步拆成一次只处理一个对象的小调用。

> **v3 修订（第二次真实运行之后）。** v2 让模型给出每个条件的"变量"（定义为"世界的一个量"），而且按 P1 删掉了全部领域例子。真实运行的结果：
> - 90 条条件中只有 33 条得到了变量；
> - 有关"人"的条件（在不在家、在做什么）几乎全部丢失，因为 7B 模型不把"在不在家"当作一个"量"；
> - 留下来的是 16 个按传感器划分的小维度（烟、一氧化碳、"烟或一氧化碳"、漏水、水传感器状态……），而且出现了"door_state"这种设备状态。
>
> 原因有两个：
> 1. **编码层次错了。** 我们的框架里，情境因子是情境层，传感器读数是证据层（由 M5 的落地配置 Γ 把读数映射成因子取值）。"烟""一氧化碳""漏水"是同一个情境问题的证据。v2 按"能否独立变化"来切分变量，就把维度切到了传感器的层次。
> 2. **只有抽象定义、没有例子，7B 模型做不好。**
>
> v3 改为按**情境问题**编码，并引入**人工码本**：研究者先手工编码一个小样本，模型照着码本编码其余条件，再用模型没见过的人工样本衡量一致性。这是质性研究中 LLM 辅助编码的标准做法。码本示例确实会命名一些维度，但它们来自语料、由人编码，在论文里如实报告；能否发现码本以外的维度，用 dev 集中 unseen 的那部分单独衡量。

> **v4 修订（2026-11-05，当前默认）：判定锚定的提升（lift）。** v3 的真实运行（20 个维度，其中 sensor_status、daytime_light、door_status 等都是读数层或设备层）说明：只要 A 阶段不看利益和标签，模型就只能问出"传感器在报什么"，因为 property 本来就是用设备语言写的。这恰好是论文要解决的表征缺口 B（把触发信号当情境）。纳入判据本身是用标签定义的（一个因子必须能翻转某个"效果 × 利益"的标签），所以发现阶段不能与标签脱钩。
>
> v4 的改法：
> 1. **编码单位改为证据单元**：一个（property，条件）对。同一条件出现在两条 property 里，编码两次，因为它"为什么重要"取决于那条 property 的动作和利益。
> 2. **每个单元一次调用（`lift_condition_prompt`）**，给出 kind、observation（证据，留给 M5）、reason（为什么在这个条件下要求/禁止该动作，对所服务的利益而言）、latent_fact（reason 真正依赖的世界事实）、counterfactual_still_right（读数为真而事实为假时，动作还对不对）、question、answer、scope。
> 3. **程序检查（`vocab._lift_check`，不调用 LLM）**：world_state 的条件本身就是事实；读数、模式、事件必须被提升到不同的事实，并且反事实回答"不对"，否则记为 lift_failed。`method.m2_lift_strict: true`（默认）时，lift_failed 的单元不进入分组，全部列在 `A2_dims.yaml` 的 `lift_failed` 里。
> 4. **提示词模板里没有任何领域例子**（`tests/test_lift.py` 检查）；few-shot 只来自人工码本。码本例子可以加 `reason`、`latent_fact` 两个字段，有才显示。
> 5. v3 保留为消融：`method.m2_coding: question`。论文里 v3 → v4 的对比（维度数、读数层维度占比、dev ARI）本身就是"为什么要锚定标签"的证据。
>
> **A2b 改为按两两关系分槽（`method.m2_grouping: relation`，默认）。** 一个槽 =（主体，方面）。
> - 主体：事实说的是谁，即提升时给出的 scope（home / room / outdoor / person）。主体不同，就不在同一个槽。
> - 方面：同一主体下，每两个事实问一次它们的关系（`fact_relation_prompt`），选项是 same（同一事实）、exclusive（不能同时为真）、a_implies_b / b_implies_a（一个蕴含另一个）、independent（可以同时为真，也可以各自单独为真）。
> - 程序建槽（`vocab._slots_from_relations`，不调用 LLM）：same 合并为一个值；exclusive 或蕴含相连的值属于同一个槽；independent 的事实属于不同的槽。如果一个连通块里有两个事实被判为 independent，说明这个槽混了两个方面，程序按依赖关系拆成团，并写进 `relation_grouping.splits` 交给人看。
> - 槽的名字和问题由每个槽一次调用给出，名字不改变结构。
> - 判据的依据：一个变量就是一组相互依赖（互斥或蕴含）的状态，不同变量之间相互独立。这就是因子化表示的定义，也是粗糙集里"条件属性"的含义。每一条槽边界都能追溯到一条被记录、可抽检的两两判断（★`m2_A2_relations_CHECK.csv`），不依赖模型怎么起名。
> - 成本：每个主体两两全问，不超过 `m2_pair_budget`（默认 2000 对）；超过时只问候选对（一次分组调用给出候选，组内全问，组间先问代表对，相关才全问）。
> - 旧的一次性分组 + 单问题验证保留为消融：`m2_grouping: llm`。
>
> A3 不变：分组的对象从"条件回答的问题"变成"事实"。A3 的赋值记录里多了 observation 一列：它就是这个取值的证据，可以直接作为 M5 落地配置的种子。

- **A2a 开放编码（每个条件一次调用，`code_condition_prompt`，few-shot 来自 `data/vocab/a2_codebook.yaml` 的 examples）：** 以下是 v3 的做法（现在是消融）。对每个条件给出 5 项：
  - kind：类型；
  - observation：观察到或设置的是什么，属于证据层，留给 M5 用；
  - question：这个条件回答的情境问题，例如"家里有人吗？""家里正在发生什么异常或危险的事？"；
  - answer：答案，保持原文的详细程度，不添加原因；
  - scope：范围。

  设备状态、配置、义务没有问题。
- **A2b 轴心编码（一次调用，`group_variables_prompt`）：** 把问的是同一件事的情境问题合并成维度（附出现次数和示例答案）。程序确定性地保证每个变量恰好属于一个维度：没被分配的单独成维度，重复分配的只保留第一次，两者都有记录。
- **A2c 单问题验证（每个多成员维度一次调用，`check_dimension_prompt`）：** 检查维度里的成员是否问的是同一个问题，即每个答案都是这个问题的一个互斥选项（规则 R2）。不是的话按模型给出的划分拆开，划分必须恰好覆盖全部成员才会执行。用利益名命名的维度会被标记出来。
- **没有轮次和停止条件：** 每个条件都被独立编码一次，质量由核对表和稳定性来衡量。
- **稳定性：** 第 1、2 次运行用温度 0.7 和不同的随机种子，并打乱变量列表的顺序。报告三项：
  - 编码类型的 κ；
  - "条件 → 维度"划分的 ARI；
  - 每个维度的复现率（Jaccard ≥ 0.5）。
- **输出：**
  - `A2_coding.yaml`：每个条件的类型、事实、变量、取值、维度、理由、property_id；
  - `A2_grouping.yaml`：变量清单、合并调用的原始回答、重复分配、每次验证与拆分；
  - `A2_dims.yaml`：每个维度的成员变量、条件数、property_id、验证结果和问题，以及各排除类型的数量；
  - `A2_runs/`、`A2_stability.yaml`。
- **可验证：**
  - `m2-dev`：拿码本中的 dev 集（22 条，模型从未见过）给 A2 打分，指标是类型准确率、"有无情境问题"的准确率，以及分组与人工分组的 ARI（全部 / 码本已有的维度 / 码本没有的维度）。**每次改提示词，先看 m2-dev，再看全量结果。**
  - `m2_A2_coding_CHECK.csv`：抽样 50 行人工核对。

### A3 维度取值（`m2-values`）

- **A3a（每个维度一次调用，`dimension_values_prompt`）：** 根据语料里观察到的取值（附次数），定义互斥且完备的取值集合，并且必须包含基线取值。阈值类表述改写成状态，例如"高于用户阈值"→"热"。
- **A3b（每个不同的事实一次闭合选择，`assign_value_prompt`，枚举 schema）：** 把每个事实分到一个取值，没有合适的就选 none_fits。这样覆盖率是精确的，每个没分配上的事实都被列出来。
- 一个维度就是一个变量，所以一个维度就是一个因子，不再需要 max_factors。
- effect_zone 由动作的目标区域派生，单独加入，并标注"不是从语料归纳的"。
- **输出：**
  - `A3_factors_corpus.yaml`：每个取值的条件数和 property_id；
  - `A3_value_assignment.yaml`：条件 → 事实 → 取值；
  - `A3_values_report.yaml`：每个维度的覆盖率、没分配上的条件、没有证据支持的取值。

### A4 人工审核（写 `data/vocab/factors_seed.yaml`，然后跑 `m2-seed-check`）

- **四条规则：**
  - R1：只描述世界状态；
  - R2：一个因子只描述一个变量；
  - R3：取值互斥且完备；
  - R4：取值是原因，不是读数。例如"烟雾报警"要写成"火灾"或"做饭"。
- **审计要求：** 每个因子都写 provenance，说明来自哪个 A2 维度、合并了哪些取值、删了什么以及删的理由。
- **`m2-seed-check` 做什么：** 检查每个因子都有 provenance，并且 provenance 指向的维度在 A2 中确实存在。然后列出审核相对 A3 改了什么：
  - 保留的取值；
  - 新增或改名的取值；
  - 没有保留的语料取值；
  - 没有用到的 A2 维度。
- **输出：** `A4_seed_check.yaml`。论文里报告"人工改动了几处"。

### B 按"效果 × 利益"引出（`m2-elicit`）

- **做什么：** 对每个效果 e 和利益 v（25 × 6 = 150 对），让 agent 回答：在哪些具体情境下，e 对 v 是不可接受的（−）或明显有益的（+）？
  - 每条回答都是一个世界事实，例如"有人在看电影""婴儿在睡觉"；
  - 每条回答要归到一个已有维度，或者 `NEW:<名字>`。
  - 这就是"开电影时会避免噪声"这类联想的系统化做法：从效果出发，想起与判断相关的情境。
- **为什么不会无限扩展：** 只会提出"会改变某个判断"的属性，而 E × V 是有限的。
- **增量：** `--effects` 只问指定的效果（例如新设备带来的新效果）。重新询问的对，旧条目会被替换；其他条目和反驳证据保留。
- **输出：** `B1_elicitation.yaml`，包含全部条目、被拒条目（及原因），以及每轮的统计（各维度、各利益）。
- **可验证：** `m2_B1_elicit_CHECK_round1.csv` 抽样 60 条，人工判断三件事：是否世界状态、标签是否合理、归属的维度是否合理。

### C 标签签名合并（`m2-consolidate`）

- **做什么（对每个有新证据的维度 d）：**
  1. **C1 规范化：** 把已有取值和证据短语改写成互斥的状态。同义说法合并，其余不合并。每个状态给出 parent，也就是现在哪个已有取值的含义包含它。
  2. **C2 签名：** R_d 是 d 的证据对，最多 30 对。对每个状态 c，问 LLM："在 d = c、其余一切寻常的情境下，e 对 v 的标签是什么"，得到签名 sig(c) ∈ {+, −, 0}^{R_d}。
  3. **C3 合并：** 签名相同的状态，对 R_d 中的每个判断都不可区分，可以合并。规则如下：
     - 已有取值不在这一步合并或删除；删除需要阶段 D 的精确证据，并由人决定。
     - 新状态并入已有取值，只限两种情况：它的 parent 就是这个取值；或者它原来没有 parent（相当于扩展这个取值的含义）。
     - 新状态的 parent 是 P，但签名等于另一个已有取值 Q：保留为新取值（相当于把 P 拆分），并标注"与 Q 不可区分"。原因是，并进 Q 会把一部分情境从 P 悄悄挪到 Q。是否合并，交给 D2 在完整判定表上决定。
     - 新维度如果没有任何全 0 签名的取值，就补一个 `none` 取值，以满足 R3 的完备性。
- **refines 映射（自动生成，供人核对）：**
  - `split`：某个取值拆成几个；
  - `extend`：新增了一个没有 parent 的取值；
  - `extend_meaning`：某个已有取值的含义扩大了；
  - `added`：新增了一个维度。
- **输出：**
  - `C1_canonical.yaml`：短语 → 状态，含 parent 和被丢弃的短语；
  - `C2_signatures.csv`：每个状态在每个证据对上的标签和机制；
  - `C3_factors_candidate.yaml`：每个取值的签名、来源和合并历史，以及 relevant_pairs 和 refines；
  - `C3_report.yaml`：每个维度的状态数和取值数。
- **可验证：** `m2_C2_signature_CHECK.csv` 抽样 60 个签名格子，人工独立给出标签，计算准确率和 κ。
- **局限：** 签名是边际的，即"其余一切寻常"。两个维度之间的交互在这一步看不到，交给 M3（在完整 Σ 上）和 D2、D3 去检验。

### D1 审核与冻结（`m2-freeze`）

- **做什么：** 人审候选词表，可以直接改文件，包括 refines。然后冻结：
  - 检查每个因子至少有 2 个取值、每个取值都有语义、每个非派生因子都有 provenance、refines 合法、能加载、Σ 非空。任何一项不满足，冻结就被拒绝。
  - 写出 `data/vocab/factors_<名>.yaml`，带 version、parent 和 refines。
  - 写出 `m2/versions/F-<名>.yaml`，记录与父版本的差异、Σ 大小，以及"有改动但没写 refines"的因子。
  - 生成规则核对表 `m2_rules_CHECK_F-<名>.csv`，供 A、B 两人各自独立填写。

### D2 粗糙集审计（M3 之后跑 `m2-audit`）

对每个"效果 × 利益"，把 K 诱导出的标签看成一张决策表：对象集是 Σ，条件属性是全部因子，决策属性是 L。所有数字都在 Σ 上精确枚举得到，不抽样（实现见 `roughset.Tables`）。

| 检验 | 定义 | 产出 |
|---|---|---|
| 因子必要性（核） | 去掉因子 q 后，有多少个等价类出现两种标签。大于 0，q 就在这一对的核里 | `D2_core_matrix.csv`（对 × 因子的冲突数） |
| 全局核 | 至少在一对中必要的因子。可以证明：向量决策的核等于各对核的并 | `D2_audit_summary.yaml` |
| 约简 | 用后向消去求最小属性集。一致性对属性集单调，所以结果不可再约简。和绑定模式实际用到的因子对照 | `D2_reducts.yaml` |
| 取值划分 | 取值 u 和 w 可以合并，当且仅当所有对、所有"其余因子相同"的情境下标签都一样。由此得到保持判定不变的最粗取值划分 | `D2_value_partition.yaml`（含两两冲突数） |
| 素性与无冗余 | 每条绑定是否为素蕴涵项（给任一文字多加一个取值，就会覆盖到标签不同的格子）；每条绑定是否覆盖了别的绑定都没覆盖的格子 | `D2_prime_check.yaml` |
| 完整判定表 | Σ × 所有非 0 对的标签 | `D2_decision_tables.csv.gz`，任何数字都能据此重算 |

**维度卡片（`D2_dimension_cards.md` / `.yaml`）：** 每个因子一张，汇总以下内容：
- 定义和取值；
- 来源：语料 / 引出 / 派生；
- 证据：支持它的 property 数及 id、引出条目数和证据对数、反驳反例数、每个取值的来历；
- 稳定性：A2 复现率；
- 必要性：是否在全局核里、在几对中必要、去掉后有多少冲突；
- 取值划分；
- 规则核对结果。

最后给出结论：
- **KEEP：** 保留；
- **DROP candidate：** 不在全局核里，K 中没有任何标签依赖它；
- **MERGE candidate：** 存在更粗的、保持判定不变的取值划分；
- **REVIEW：** 有人判定某条规则不通过。

### D3 反例引导的细化（`m3-refute` → `m2-refine`）

- **要反驳的断言：**
  - 每条 + / − 绑定；
  - 每个"效果 × 利益"的封闭世界 0 区域。先用素蕴涵覆盖把 0 区域表示成若干乘积项，每对最多取最大的 4 个；一条绑定都没有的对，就是整个 Σ。
  - 只反驳 + / − 会漏掉一种错误：K 把有害的情境当成"无关"。这正是"漏判"的来源，所以 0 区域也要反驳。
- **流程：**
  1. **反驳者**针对一个断言，提出至多 3 个现实情境。每个情境给出叙述、全部因子的取值、它应得的标签，以及因子没有捕获的属性。
  2. **有效性：** 给出的取值必须真的落在断言的模式里，也在 Σ 里，并且应得标签不同于断言。
  3. **非虚假：** 一个看不到断言、因子和期望标签的独立裁判只读叙述，独立给出标签。它的标签与期望标签一致，才算确认的反例。
  4. **细化：** 确认的反例说明"两个现实情境落进同一个格子，却应得不同的标签"，也就是抽象过粗。`m2-refine` 把缺失属性归到已有因子（结果是拆分取值）或新维度，写成新的证据条目（source = refutation），并给出下一步命令。
- **输出：** `m3/refutation.yaml`（每个断言、每个反例、裁判标签、是否确认；虚假反例数；缺口统计）、`D3_refinement.yaml`、`m2_D3_counterexample_CHECK.csv`（人工判断反例是否真实）。

### 下一版本（增量、可扩展）

```
m2-consolidate --base current --dims <D3 给出的维度>   # 只重建受影响的维度
(人审) m2-freeze --src … --name v2                      # 记录 refines 和差异
(改 config) vocab-migrate --old data/vocab/factors_v1.yaml
m3 --only-stale                                         # 只重建待复核的对
m2-audit
```

- **迁移规则（`vocab-migrate`）：**
  - 被拆分的取值，在旧模式里替换成它的全部子取值，这样旧含义不变；
  - 被合并的取值，映射到保留的那个；
  - 新维度在旧模式里不受约束。
- **以下"效果 × 利益"对标记为待复核：**
  - 约束了变化因子的绑定所在的对；
  - 变化因子的证据对；
  - 迁移后 + 和 − 区域重叠的对。
- 旧 K 存为 `spec_F-v1.yaml`。
- **新设备、新效果：** 先跑 `m2-elicit --effects <新效果>`，再跑 `m2-consolidate --base current`，然后冻结、迁移，最后跑 `m3 --effects <新效果> --merge`。
- **新 property（`m2-ingest --src <csv>`）：** 新 property 先用当前词表映射。能表达的，词表不动（不需要就不长）；不能表达的，才对它的条件做同样的提升和 `_lift_check`，把提升出的事实归到已有因子或 `NEW:<名字>`，写成证据条目（source = property），再交给 `m2-consolidate --base current`。是否成为新取值，仍由 C 阶段的见证规则决定：签名必须与父取值不同。语料留出集里的 property 会被拒绝，因为它们用来衡量可表达性。输出 `I1_ingest.yaml` 和 ★`m2_I1_ingest_CHECK.csv`。

**扩展的接受规则（四条都满足才冻结下一版）：**
1. 见证：新增或拆分的取值在至少一个"效果 × 利益"上与父取值签名不同；合并或删除在完整判定表上零冲突（D2）。
2. 规则：R1–R4 两人核对通过。
3. 预算：任一"效果 × 利益"的投影格数不超过 200（`vocab-metrics` 的 projected_table_size）。
4. 不倒退：留出集的可表达率不下降（`m2-map` + `vocab-metrics`）。

## 4. 第二章 2.5 节的理论：用了吗？用在哪？

| 理论 | 是否使用 | 具体位置 | 支撑的论断 | 需要如实说明的地方 |
|---|---|---|---|---|
| 2.5.1 因子化表示 | 是 | `model.Vocab`：Σ = ∏D 减去可行性约束 | 情境的异同落实到具体变量；约束可以只涉及部分变量 | 无 |
| 2.5.1 粗糙集决策表 | 是，在三处 | ① D2 审计 `roughset.Tables`：核、约简、取值划分，在 Σ 上精确计算；② C 的签名合并：单个维度的边际决策表上的取值粒化；③ `vocab-metrics` 中因子和取值的消融，与 D2 是同一套计算 | 核对应因子的必要性；保持判定的最粗取值划分对应粒度原则；全局核等于各对核的并 | 在 Σ 上，决策表对全体因子永远是一致的，因为每个格子就是一个对象。"一致性"真正要检验的对象是现实情境（第 3 行的 CEGAR），而且只能抽样证伪，不能证明。C 是边际近似，不是精确的约简 |
| 2.5.2 逻辑最小化与素蕴涵项 | 是，在 M3 和审计中 | `minimize.py`：EXPAND 产生素蕴涵项，IRREDUNDANT 贪心选覆盖；`verify` 检查覆盖无损；D2 逐条检验素性和无冗余；D3 用它把 0 区域写成乘积项 | 条件化绑定是多值素蕴涵项；覆盖与逐格标注等价 | 覆盖是无冗余的，但不保证项数最少（没有做 Quine–McCluskey 的精确覆盖）。论文写"素且无冗余的覆盖（ESPRESSO 式启发式）"，不要写"最小覆盖" |
| 2.5.3 Kleene 三值逻辑 | **M2 不用** | `model.match3`、`grounding.py`、`adjudicate.py`：在线判断时有因子未知 | 未知不当作真也不当作假，交给"询问"处置 | 建议第四章把它放在运行时落地和裁决那一节引用，不要放在词表这一节 |
| 2.5.4 反例引导的抽象细化 | 是，在两层 | ① M3 的 O3：抽象区域的"标签一致"断言，用区域内抽样的格子做点标注来检验，不一致就按反例拆分区域；② M2 的 D3：反驳 → 裁判剔除虚假反例 → 细化词表 → 迁移 → 再验证 | 词表过粗时能被发现，并且按反例细化 | 没有形式化的具体系统，"反例是否真实"由独立裁判加人工核对表判定；搜索不穷举，所以是证伪而不是证明；终止条件是预算和轮数（建议至多 2 轮） |

另外，"情境就是与交互相关的信息"（Dey 2001）在这里被操作化为：一个因子属于词表，当且仅当它在某个"效果 × 利益"的核里。

## 7. 可扩展性实验（论文里证明"可扩展"）

**实验 X1：新效果增量。**
1. 从 M1 的效果中留出只由 1/3 动作产生的效果，记为 E_new，其余记为 E_old。
2. 增量构建：
   ```
   m2-elicit --effects <E_old>、m2-consolidate、冻结 v1a、m3 --effects <E_old>
   m2-elicit --effects <E_new>、m2-consolidate --base current、冻结 v1b
   vocab-migrate、m3 --only-stale、m3 --effects <E_new> --merge
   ```
3. 全量对照：在同一个 v1b 下跑一次 `m3 --spec-out out/m3/spec_scratch.yaml`。
4. 报告：
   - `k-compare` 的一致率和 κ，衡量局部重建是否等价于全量重建；
   - 增量节省的 LLM 调用；
   - E_new 引出的新取值和新维度数，说明扩展只在需要时发生；
   - v1b 与"一次性全量引出"的词表之间的差异，说明词表对加入顺序的依赖程度。

**实验 X2：CEGAR 轮次。** 报告每一轮的确认反例数、新增或拆分的取值数、留出 property 的可表达率。期望确认反例逐轮下降。

**冒烟示例（mock，仅用于说明机制，不是结果）：**
1. v0 词表中，"声音增大 × 舒适"的 0 区域被反驳：有人醒着在看电影，噪声不可接受。裁判确认了这个反例。
2. refine 把它归到 zone_occupant，consolidate 新增取值 watching_a_movie（awake 拆分）。它的签名与 asleep 相同，所以被标注为"与 asleep 不可区分"。
3. 冻结为 v0b 后，迁移把两对标记为待复核，只重建了这两对；与全量重建相比，K 的一致率为 1.0。
4. D2 审计显示，watching_a_movie 与 asleep 在"开门 × 安全"上判定不同，所以不能合并。这说明 C 的边际签名不足以决定合并，最终要由 D2 在完整决策表上精确判定。

**调用量估计（E = 25，V = 6，约 170 条训练 property）：**

- A2 每次运行约为：条件数 + 1 + 多成员维度数（146 条时约 160 次），3 次运行约 480 次；
- A3 约为：维度数 + 不同事实数（约 150 次）；
- B 150 次；
- C 约为（每维状态数 × 证据对数）之和，约 1000 次；
- D3 约为（绑定数 + 0 区域断言数）×（1 + 裁判次数）。

---

## 9. 局限（Threats to Validity 直接用）

1. **自己出题、自己判。** 同一个模型既提出维度又给标签。缓解办法：签名、反例、K 都有人工核对表；可以换一个模型复核一部分。
2. **语料偏向安全。** 用 A1 的按利益覆盖率来量化这个偏差，用 B 对 6 项利益全覆盖来弥补。
3. **C 是边际近似。** 交互由 M3 和 D2、D3 检验。合并只在 D2 有精确证据并经人工确认后才做。
4. **CEGAR 是证伪，不是证明。** 反驳搜索不穷举，裁判也是 LLM。所以报告虚假率和人工确认率，并限定轮数。
5. **稳定性来自采样。** A2 的稳定性来自温度 0.7 的重复采样，跨模型稳定性需要换模型另跑一次。
6. **规则核对样本小。** 因子只有约 10 个，κ 的置信区间宽。如实报告样本量。
